# 维度方阵

适用本整合包 Minecraft 1.21.1 / NeoForge 21.1 / Custom Machinery 0.10.72。
机器及配方使用 Custom Machinery 和 KubeJS，小型扩展模组负责投影、惯性、分阶段音效、客户端状态同步和 JEI 多方块搭建图。

## 结构与使用

- 外接尺寸严格为 **11×11×11**，包含底座与边框。控制器位于正面第 2 层中央，朝向结构外侧；支持四个水平方向。
- 默认结构为装甲 **56**、框架 148、相位导轨 101、约束节点 28、**高维投影模块 4**、控制器 1，共 338 个方块、993 格空气。左右墙面允许选装能量接口，背墙允许选装冷却接口，内部空气位仍需保持。
- 旧版结构需要将底座图纸坐标 `(3,0,3)`、`(3,0,7)`、`(7,0,3)`、`(7,0,7)` 四处装甲换成高维投影模块。坐标从0开始；可在JEI底层图中逐格确认。通电后模块发光并向中央投射光束。
- 电源可从左墙输入接口接入，右墙输出接口可向外供能；原控制器输入仍兼容。物品管道继续接到控制器。三个输入槽、一个输出槽，接口与控制器共享原有 100,000,000 FE 储能。
- 结构完整且内部储能大于零时，中央用 **4 秒渐入**显示透明四维超立方体。待机投影不耗电；断开线缆后仍有储能时继续显示。
- 配方运行后用 **4 秒加速至 1,440°/s（240 rpm）**，是初版主轴速度的 9.6 倍。结束、暂停、缺料或缺电后用 **3 秒制动至零**；中途续配方或恢复运行会继承当前速度。高速状态叠加七层短曝光残影与环形轨迹。
- 断电或结构破坏时投影用 **3 秒淡出**。逻辑按游戏 tick 积分，逐帧采样，因此帧率不影响转速，暂停游戏时也不继续旋转。
- 机器配方每 tick 使用 Custom Machinery 原生结构检查。待机投影每 10 tick 检查结构；同步形成、供电、运行状态以及热量和冷却液，无需打开 GUI，也不会遍历世界搜寻机器。

控制器由原子合金、传送核心、终极控制电路、固态维度核心和下界合金锭合成。四类结构件均有工作台配方，可通过 JEI 查阅。

共振配方：16 末影珍珠 + 16 紫水晶碎片 + 4 福鲁伊克斯水晶 → 1 维度共振晶体，耗时 60 秒，32,768 FE/t，总耗能 39,321,600 FE。产物为独立新物品，没有替换已有配方，也没有新增任务依赖。

## 投影模块、冷却与热失控

高维投影模块是必需结构件，四个模块由扩展原生注册，均有工作台合成。通电后亮度15，光束从模块顶面汇入中央；原有4秒渐入、3秒淡出和高速旋转保持。模块不是虚拟方块，底座未补齐时机器不能形成。

**背墙的9×9区域**可把原结构件或墙面空气替换为 `poc_dimension_matrix:coolant_input_port`，不含底座、顶框和左右立柱。接口自动朝背面墙外侧，支持流体管道推入和在外侧用水桶灌入，只进不出。所有冷却接口共用控制器 **64,000 mB** 储罐；默认冷却液是水。允许流体由 `data/poc_dimension_matrix/tags/fluid/coolants.json` 标签定义，整合包可用同名流体标签扩展。右键接口可查看共享液量和热量。

热量范围 **0–10,000**。运行每tick需求5mB（每秒100mB，60秒配方共6桶）；足额供应时每秒降120热量，任何供液缺口都会按缺口比例升温。从零热量完全缺液连续运行 **120秒** 达到上限。停止配方后无液每秒自然降25，有液则消耗每秒20mB、降100；热量为0时待机不耗液。液量、热量和失控标记随控制器NBT保存。

中央全部虚拟几何随热量由蓝经黄变红；抖动幅度从0.004格增加至约0.254格。热量达到40%开始警报，间隔由3秒逐渐缩短到0.25秒，同时提高音调和音量；降温后逐渐减弱。警报为新的0.22秒原创声音，支持字幕和“方块”音量控制。

**配方实际运行时，进入内部9×9×9空间的玩家每0.5秒扣4生命，每秒8生命。** 直接扣实际生命，跳过护甲、吸收心、抗性、伤害冷却及创造免伤；保留原生受伤/死亡消息，创造模式同样可能死亡。JEI图纸预览不创建世界机器，不会触发伤害或热量。

热量封顶会移除控制器、触发冲击爆炸并生成约45秒的蘑菇云发射效果。地形破坏范围以机器中心所在区块/区块节对齐：水平方向11×11个区块，垂直11个16格区块节，即 **176×176×176格**，世界高度边界处裁剪。最多扫描5,451,776个方块格，基岩等不可破坏方块保留，其余受影响方块直接气化，不生成方块掉落实体；范围内玩家也受到致命冲击伤害，包含创造模式。

大范围地形清理采用从中心向外的持久化队列，每维度每tick最多尝试16,384格且采用4ms软时间预算，一次仅处理一个目标区块的临时加载票据。区块尚未加载时异步等待，不同步等待生成；任务存于维度的 `poc_matrix_meltdowns` SavedData，正常保存重启后继续。超大范围并非单tick完成；单个方块自身的模组移除逻辑仍由对应模组执行。

## 阶段音效

维度方阵新增通电启动、加速、最高速、减速四种原创电子机械音效。声音位于阵列中心，按空间距离衰减，音量使用游戏的“方块”分类，并提供中英字幕。通电提示播放一次；加速、最高速和减速使用独立的无缝循环，音高、音量跟随实际转子速度，衔接处用 4 tick 交叉淡化。原有 4 秒加速与 3 秒制动保持。

连续配方处于最高速时保持同一条循环，中断后续转会从当前速度衔接。停止后循环退出；方块移除、换世界、区块卸载或离开 48 格范围后释放声音。资源重载后会恢复当前循环；静音后取消静音也会恢复。待机静止时不常驻播放噪声。

资源位于 `assets/poc_dimension_matrix/sounds/`，四段均为 44.1 kHz 单声道 Vorbis OGG、2 秒长；`sounds.json` 注册声音和字幕。`build-sounds.mjs` 确定性合成音色，不使用第三方采样。重新生成命令：

```powershell
node tools/poc-dimension-matrix/build-sounds.mjs '<FFmpeg.exe路径>'
```

试听文件的时间轴为 0 秒通电、3–7 秒加速、7–11 秒最高速、11–14 秒减速，最后 1 秒静音；它是离线混音示例，实际播放由游戏的转子状态、距离和音量设置控制。

## JEI 多方块搭建

新增 **“整合包多方块搭建”** 分类，读取客户端收到的 Custom Machinery 实际配方中的结构要求。当前覆盖虚空采矿机、染色工厂、流体处理机、结构检测器、维度方阵五类控制器，源脚本合计 17 份结构定义。同一机型的相同图纸去重，长材料清单每 18 项分页；多重结构条件会提示查看同机型相关图纸。

旧 `logs/custommachinery.log` 显示前四类机器因 `name` 缺少 `text` 包装而被跳过。本次同步将这四份定义的名称包装改成当前 CM 要求的 `name.text`，保留原翻译键、颜色、配方及其余参数。维度方阵此前已使用正确格式；其它非多方块机器的旧问题未扩大范围修改。

控制器上按 **R** 可查看搭建页，材料上按 **U** 可查询用途；原有加工和工作台合成分类继续由对应模组提供。两个现有一键搭建模板也关联到对应结构。图纸中的材料数量为默认结构所需数量，控制器另列，维度方阵可选接口另列；不会生成新的加工或合成配方。

- 预览区滚轮连续缩放，范围 **0.2–16 倍**，以鼠标所在位置为缩放中心。
- 整体视图左键拖动旋转，右键拖动平移；分层视图左右键拖动均可平移。
- 下方 `< >` 每次转 90°，`- +` 逐层查看，点击中间按钮重置视角、缩放和平移。
- 悬停三维方块或分层格，显示本地化方块名称、相对控制器的坐标和方块状态；有替代方块的位置会显示允许列表。
- 原始空格表示不限制该格，明确的 `minecraft:air` 才必须留空。维度方阵左输入、右输出的范围和默认材料数量均保留。

三维预览读取 Minecraft 原生烘焙模型四边形，先用生产矩阵投影并按深度排序，再走 `position_tex_color` GUI贴图着色器绘制；显式关闭三维深度和剔除，避免原实体渲染管线出现“有悬停信息但画面空白”。资源重载会重建网格。控制器自带特殊实体渲染且没有普通烘焙面时，用磁石方块作原点标记，名称仍显示真实控制器。射线悬停和绘制共用矩阵。不会放置世界方块、修改控制器或播放机器运行音效。JEI 为可选的客户端集成；服务端声音注册、接口和机器逻辑不依赖 JEI。

## 左右墙能量接口

**站在机器互动面前，面向控制器**确定左右，随控制器水平朝向一起旋转。左墙只允许青蓝的**能量输入接口**，右墙只允许金橙的**能量输出接口**。

每侧墙面均有 **9×9 个可选位置**：从底座上方第 2 层至顶框下方第 10 层、从前方立柱后至后方立柱前。可替换这些位置原有的框架、导轨、约束节点，也可直接占用墙面上的空气位；底座、顶框、前后立柱和正背面不属于接口区。接口为可选件，原有无接口结构照常成立。

两个独立方块可在 JEI 查询工作台配方：

- 输入：`poc_dimension_matrix:energy_input_port`，装甲×4、金锭×1、红石×2、漏斗×1、基础控制电路×1。
- 输出：`poc_dimension_matrix:energy_output_port`，材料相同，但以活塞代替漏斗。

接口每 10 tick 由控制器自动绑定，无需工具或额外配置；结构完整后自动转向墙外侧并亮灯。外侧接线，输入口只接收 FE，输出口只输出 FE，并主动向外侧相邻线缆/储能推送；同时支持线缆主动提取。右键接口可查看是否连接和共享储能。

同一方阵的**所有输入接口合计 1,000,000 FE/t，所有输出接口合计 1,000,000 FE/t**，两个方向各自独立计额。接口无独立储能，模拟请求不耗能、不占额度。拆除接口、放错左右墙、破坏结构或卸载控制器区块后停止传输；传能时共享的原生结构检查每 tick 最多执行一次，不会强制加载区块。控制器原有直接输入独立保留。

方阵的输出来自已有共享储能，这次功能没有加入发电配方。输出过快耗尽储能时，原有配方会按 Custom Machinery 的能量规则暂停。

`structure.json` 的 `base_pattern` 保存默认图纸及材料清单（含四个投影模块），`pattern` 为支持选装接口的检查图纸；墙面符号的 `keys` 是“原方块或该侧正确接口”的二选一列表。服务端待机检查和 KubeJS 配方读取同一份规则。改图后仍需重新构建扩展。

## 四维全息渲染

`HologramScene` 根据四维超立方体的 **16 个顶点、32 条棱、24 个正方形面**生成几何。先在 XW/YW/ZW 三个四维平面旋转，再做 4D→3D 透视投影，最后进行三维主轴旋转，因此运行中会出现真正的四维投影形变。中心没有不透明实体内核。

材质使用原生 `POSITION_COLOR` 着色器及 `SRC_ALPHA + ONE` 加色混合；白亮细棱、青蓝/紫色边光及由顶点 alpha 插值生成的透明光晕共同形成自发光。无需外部光影包或后处理。保留世界深度测试、关闭深度写入及背面剔除，结构方块会正常遮挡投影，透明核心各层不会互相切掉。

内部装饰包含交错倾斜轨道、六个沿轨道运行的数据星点、四角全息标尺与浮动菱形节点、能量丝、四面动态分段码数据板、底部阵列网格/环形刻度、上下扫描环及上行投影光束。所有装饰均为虚拟几何，不增加结构方块。静止约 7,532 顶点/帧，高速约 9,388 顶点/帧；残影强度随实际转速平滑变化。

这些效果产生投影自身的亮度和光晕；四个实体投影模块通电后提供实际光照，投影几何本身仍不放置世界方块。原机器储能和共振配方保持；结构新增四个必需模块、背墙可选冷却入口。

## 离线构建与核验

在整合包根目录执行；使用 Node.js 和本机 JDK 21 或更新版本，不需要 npm 包：

```powershell
node tools/poc-dimension-matrix/generate-assets.mjs
node tools/poc-dimension-matrix/build.mjs --jdk '<JDK目录>' --classpath-file '<本机javac参数文件>' --test --preview
```

默认编译类路径从本机 `tools/poc-cursor/build/javac.args` 读取。跨机器构建时提供自己的安全 javac 参数文件，包含 `-classpath` 行及下一行的 Minecraft/NeoForge/依赖 JAR 路径；脚本额外加入当前已安装的 Custom Machinery。Mixin 离线检查需要本机 LaunchWrapper，可通过 `--launchwrapper` 指定。

搭建图编译还会加入本机 JEI JAR。`audit-structures.mjs` 用隔离的只读 recipes mock 收集源脚本结构，供离线检查覆盖范围；运行中的 JEI 页面直接读取游戏实际加载的配方，不读取该检查快照。

`generate-assets.mjs` 确定性生成本功能的结构、模型、贴图、语言和投影几何；不要在手改这些文件之后直接运行生成器，否则会重新生成。`build.mjs` 将当前结构和投影数据原样打包到扩展中。因此手改结构或投影数据后，也需要重新构建扩展，避免服务端待机判断与配方图纸不一致。

离线检查覆盖 Java 21 编译、结构连通性/空腔/尺寸、接口四朝向/162 个选装位置/并联限流/模拟传输/回压退款/能量守恒、超立方体拓扑/真正四维形变/投影边界/相位连续/透明网格、4/3 秒显隐与起停、转子积分与中断续转，并用实际 Mixin 0.8.7 转换本机 Custom Machinery 的服务端方块实体与客户端渲染器。离线 LaunchWrapper 宿主会提示 JAVA_21 平台和 FML 初始化警告；它只是字节码检查宿主，不是 NeoForge 游戏启动。

新增检查覆盖音效上电边沿/速度阶段/连续配方/中断续转，全部 17 份图纸的坐标/控制器/默认材料，四个视角与 0.2–16 倍缩放后的射线命中和鼠标锚点，以及本机 JEI 原生 `OffsetJeiInputHandler` 对模拟输入、页面偏移、滚轮、拖动、按钮和物品槽事件的处理。OGG 的时长、声道、解码峰值、循环周期和字幕引用另有离线核验；没有进入游戏实测声音混音或完整 JEI/光影组合的最终画面。

## 自动成形与工艺动画

当前生产渲染器使用FormedMachineScene，替代第一版MachineFxScene的漂浮装饰。完整结构无需通电即可成形；服务端首次tick及每10tick用原生结构匹配同步状态。配方RUNNING控制机械机构，停止约1秒制动，断电保留机壳；结构失效恢复原方块外观。时间晶体模块与原子主体共用控制器，完整时显示附加线圈。

FormedMachineVisuals按原结构的非空气成员登记遮罩；FormationMask以引用计数支持重叠成员，使用并发成员表供区块工作线程只读。原版与本机Sodium 0.6.13的方块/流体烘焙、原版方块实体分发器均有可选客户端Mixin；Sodium目标使用Pseudo和Coerce，不要求安装Sodium。成形和恢复只使相关区块段重绘，卸载控制器或切换世界后清理。控制器仍执行本扩展整机渲染，但跳过旧CM动态模型。

所有世界方块、库存、能力接口和原碰撞保持，没有世界方块替换或物品搬移；原结构中的空气不会因模型增加碰撞。结构、材料、配方、任务和模板本轮保持，维度方阵不参与遮罩。各模型工艺说明、前后对照与8秒动图见design/machine-formed-20261023/；本轮修改前150份文件和旧JAR保存在该目录backup/及before-formation-backup.zip。
