# 任务建筑模板修复

任务奖励中的 Building Gadgets 2 模板保存 `gadget_uuid`、`copy_uuid` 和名称，不包含建筑方块数据。模板管理器根据 `gadget_uuid` 从当前世界的 `data/buildinggadgets2.dat` 查找建筑。只有奖励物品而没有相应存档数据时，预览为空，“载入”也会失败。

2026-10-06 检查实际 PCL 实例：`新的世界 (7)` 中保留全部 7 个任务建筑 UUID，`新的世界 (19)` 中只有一个玩家自建建筑 UUID，没有任务模板的对应数据。游戏日志中“虚空采矿机-5”和“原子再构室”的物品 UUID 与任务奖励一致。因此本次修复补齐每个世界需要的数据。建筑小帮手 JAR 在此前批量更新前后均为 1.3.9。

## 修复内容

- `kubejs/server_scripts/quest_building_templates.js`：附带从制作存档恢复的 7 份建筑数据，包含方块状态、坐标范围和完整位置数组。进入世界时，仅补齐缺失或空的任务建筑记录，调用模组自身的 `BG2Data.addToCopyPaste` 保存。
- `templates.json`：与脚本内数据一致的审查备份，方便查看或重新导出；脚本运行时直接使用其内置数据。
- `manifest.json`：记录 UUID、任务文件位置、建筑尺寸、方块数量和状态表，涵盖实际实例中的 11 个奖励条目；其中部分奖励共用同一个建筑 UUID。

保留原奖励 UUID，所以已领取的模板也能使用。玩家已有的非空建筑数据不被覆盖。没有修改任务内容、任务依赖、配方或正式存档文件；新旧世界均在下一次进入时自动补齐。

模板包含大型流体处理器的两个不同 UUID、虚空采矿机 3/4/5、染色工厂和原子再构室。“大型流体处理器-药水酿造”沿用原任务共用的建筑 UUID。

## 验证方法

在使用当前模组集合、Minecraft 1.21.1、NeoForge 21.1.255 的隔离客户端中重新启动并进入测试世界：逐一检查原方块 ID/属性、预览数据序列化、模板管理器实际载入方法，以及发送后客户端的模板/工具预览缓存。保存后读取实际写入的存档数据，核对建筑内容与玩家自建模板的保留情况。验证结果见 `validation-log.txt`。

测试实例和临时验证脚本位于 `E:/minecraft/.codex-validation/58b1-3267-server`；临时验证脚本不部署到整合包。

模组源码参考：[Building Gadgets 2](https://github.com/Direwolf20-MC/BuildingGadgets2)。本次方法签名和读写行为另以本机 1.3.9 JAR 的 `BG2Data`、`PacketUpdateTemplateManager` 字节码核对。

## 使用

完整重启游戏并进入世界，再打开模板管理器，放入任务模板和复制粘贴工具，执行载入。已领取的模板无需重新领取。
