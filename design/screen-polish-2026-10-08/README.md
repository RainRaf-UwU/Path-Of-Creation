# 创世之径 · 加载页和菜单细节

已接入本地。保存并退出游戏后重新启动一次，加载新注册的 FancyMenu 页面与图片缓存。实际游戏画面由用户验收；本轮没有自动操作游戏。

查看 `preview.html` 或 `preview-overview.png`。加载页显示的 64% 是静态预览样本，游戏中的自定义进度条与百分比接入真实加载数据。等待阶段用约 2 秒的扫描光循环，没有固定百分比。

## 本轮设计

- 加载页：原创无文字机械方块背景、青紫创世轨道、独立品牌标题、自定义双语阶段铭牌、进度轨道、扫描光。隐藏原生加载文字与区块生成图，覆盖世界准备、生成、数据处理、接入四个过渡页。
- 主菜单：原布局不改，增加双层轨道、编号铭牌、紧固点、面板细线和边缘刻度。
- 世界选择：两侧增加芯片、电路、定位点和归档铭牌，头尾强化细线刻度；中央存档和全部操作由原生控件处理。

本轮世界加载 Screen 不包含启动器、NeoForge 早期窗口或 Minecraft 资源重载 LoadingOverlay。资源重载属于另一类界面。

## 素材与复现

`assets/` 是独立图片和 GIF；`layouts/` 是 FancyMenu 原生布局；`tokens.json` 记录颜色、坐标、字体及状态；`PRD.md`、`TECH-SPEC.md`、`DESIGN.md`、`QA.md` 记录设计与验证边界。

背景采用内置 imagegen 生成（提示词见 `imagegen-prompt.txt`），原始生成文件逐字节保留到 `assets/loading-background.png`；其余是确定性界面素材，不将文字烘焙进背景。生成结果实际尺寸 1672×941。

`build_screens.py` 默认重新生成候选/预览/安装计划，不修改游戏配置；`--install` 只安装当前计划，校验每个目标的前后 SHA-256、备份原文件并保护游戏内容。首次安装已经完成，不要直接再次安装旧计划。同名原始备份不会被覆盖。

## 备份与验证

接入共 25 文件：19 PNG、1 GIF、4 布局、1 可定制名单。9 个原装饰图片和原名单共 10 文件有备份，另外 15 文件为新增；备份在 `.cache/screen-polish-20261008/backup/`，完整范围见该目录上层 `installation.json` 和本目录 `installation-plan.json`。

752 个 KubeJS 资源/脚本/数据、任务、options、FML 和原菜单等保护文件哈希不变，260 个原有模组 JAR 大小/修改时间不变。没有改变配方、任务依赖、存档、个人设置、原菜单动作，也没有提交、推送或发布。

原生 FancyMenu 文件解析、进度元素序列化往返、百分比来源和隐藏控件 ID 检查通过；三种 GUI 尺寸边界检查通过。原生 TextElement 需要运行中的游戏字体，离线验证只核对它的来源与模式，不冒充字体渲染/实际屏幕验收。

回退时先退出游戏，再仅恢复清单中有备份的原文件；新增文件只在仍匹配本轮哈希时移除。不要删除整个 FancyMenu 目录。
